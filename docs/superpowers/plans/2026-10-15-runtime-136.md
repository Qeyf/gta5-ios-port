# GtaV Mobile 1.3.6 implementation plan

**Goal:** fix the supplied 1.3.5 device regressions and remove verified obstacles to 120 Hz gameplay, preserving UIKit/Metal and English/Turkish support.

**Scope:** bounded changes to existing input, startup, graphics configuration and diagnostic delivery. Use Apple's documented APIs and existing project architecture. Keep the device-local game files and private versioned build/release workflow.

## Evidence and constraints

- Both new device logs used the 60 FPS engine cap; neither measures 120 FPS.
- RAPIDGT's raw I key triggers `[wasm] debug flight toggled (on)` inside console entry. Console UTF-16 text delivery is separate from raw key state.
- WORLD_READY waits for pipeline compilation quiescence; it is too late for touch availability. Startup control status alone can be transient and is insufficient to prove loading ended.
- Startup display-link preferences are read before the Home settings can change. Synchronize them again with the cap actually used by Play.
- Apple documents LSSupportsGameMode on iOS/iPadOS 18.6 onward; retain the old Game Mode key for earlier supported systems.
- The three extra developer emails were prior synthetic setup tests. The player's actual note/log report was delivered once. Send no real test emails in this task.
- The raw startup log is currently opt-in by launch argument. Enforce its exclusion from production UI and keep crash details in explicit Share/Send actions.
- Device combat tail includes AI/vehicle-avoidance dependency stalls, with spare memory and no recorded I/O or producer backpressure. Do not claim 120 FPS without a physical-device run or blindly change synchronization.

## Review focus

- A console letter must never become a flight/debug/gameplay key, including cancellation and slow input delivery.
- A transient controllable player during loading must not reveal controls; pipeline compilation must not delay a genuinely playable player.
- Home changes and relaunches must use the same frame cap in the engine and display link, including 60 Hz hardware.
- Crash recovery must not expose raw JSON or assert an unproven memory kill.
- Cancel/reopen and repeated taps must not launch overlapping report uploads or leak the recipient.
